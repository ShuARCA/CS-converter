## 1. 概要

### 1.1 システム目的

クトゥルフ神話TRPG（CoC6版）のキャラクターシートを、以下の3つのサービスから取得し、オンラインTRPGツール「ココフォリア」で使用するJSONデータに変換するWebアプリケーション。

| 対応サービス | URLパターン例 |
|---|---|
| いあきゃら（通常） | `https://iachara.com/view/{数字ID}` |
| いあきゃら（SNS） | `https://iachara.com/sns/{数字ID}/view` |
| キャラクター保管所 | `https://charasheet.vampire-blood.net/{数字ID}` |
| キャラエノ | `https://charaeno.sakasin.net/6/{数字ID}` |

### 1.2 設計方針

- **サーバーレス**: すべての処理をブラウザ側で完結させる（静的HTML/CSS/JS）
- **無料運用**: GitHub Pages、Netlify、Vercel等の無料ホスティングで動作
- **CORS回避**: 無料CORSプロキシを活用。プロキシ依存リスクを複数列挙し対策する
- **保守性**: モジュール分割・定数集約・単一責任原則・インターフェース明示
- **堅牢性**: 外部サービスのHTML構造変更を想定した防衛的パース設計

### 1.3 対象外

- 7版キャラクターシートへの対応（6版のみ）
- ローカルのExcelファイルからの変換
- ユーザーアカウント管理・サーバー側永続化

## 2. 技術スタック

| 要素 | 採用技術 | 理由 |
|---|---|---|
| 言語 | HTML5 / CSS3 / Vanilla JavaScript (ES2022+) | サーバー不要・ゼロ依存 |
| モジュール | ES Modules (`type="module"`) | ファイル分割・保守性 |
| スタイル | CSS Variables + Flexbox/Grid | テーマ管理容易 |
| データ取得 | `fetch()` + CORSプロキシ（後述） | 無料・サーバーレス |
| JSON生成 | ネイティブ `JSON.stringify()` | 追加ライブラリ不要 |
| HTMLパース | `DOMParser` API | 標準API・XSSリスクなし |
| ホスティング | GitHub Pages / Netlify（静的配信） | 無料・サーバー不要 |

### 2.1 ES Modulesのローカル動作制限

ES Modulesは`file://`プロトコルでは動作しない（CORS制限）。  
**対応**: README.mdに「ローカル確認は `npx serve .` 等でHTTPサーバーを立ててください」と明記する。

## 4. データモデル

### 4.1 正規化キャラクターデータ（内部表現）

各パーサーが出力する共通フォーマット。全パーサーはこの型を返す契約とする。

```typescript
interface CharacterData {
  // 基本情報
  name: string;          // キャラクター名（空文字列不可、パース失敗時は "名無し"）
  memo: string;          // キャラクターメモ（常に空文字列。将来拡張用）

  // 能力値（取得失敗時は 0 を格納、isPartialを立てる）
  stats: {
    STR: number;
    CON: number;
    POW: number;
    DEX: number;
    APP: number;
    SIZ: number;
    INT: number;
    EDU: number;
    currentHP:  number;  // 現在HP（保管所・いあきゃらから取得。なければmax_HP）
    maxHP:      number;  // 最大HP = floor((CON + SIZ) / 2)
    currentMP:  number;  // 現在MP（なければmaxMP）
    maxMP:      number;  // 最大MP = POW
    initialSAN: number;  // 初期SAN = POW × 5
    currentSAN: number;  // 現在SAN（取得失敗時はinitialSANを使用）
    idea:       number;  // アイデア = INT × 5
    luck:       number;  // 幸運 = POW × 5
    know:       number;  // 知識 = EDU × 5
    DB:         string;  // ダメージボーナス文字列（"+1d4" / "-1d4" / "+0" 等）
                         // API/HTMLから取得できない場合はconstants.jsのDB表で算出
  };

  // 技能リスト（全60技能分を格納。初期値のみのものも含む）
  skills: SkillEntry[];

  // パース診断情報
  isPartial: boolean;    // true = 一部フィールド取得失敗があった
  parseWarnings: string[]; // 警告メッセージリスト（UIに表示）

  // ソース情報
  sourceUrl:  string;
  sourceType: 'iachara' | 'iachara_sns' | 'hokanjo' | 'charaeno';
}

interface SkillEntry {
  name:        string;   // 技能名（constants.jsのSKILLS定義に合わせる）
  displayName: string;   // 表示名（括弧内の専用名を含む場合あり。例: "運転(自動車)"）
  value:       number;   // 技能値（現在値）
  initial:     number;   // 初期値（計算済み）
  isAcquired:  boolean;  // value > initial であれば true（取得技能）
}
```

### 4.2 ユーザーオプション（UI設定）

```typescript
interface Options {
  // チャットパレットコマンド種別
  // "1d100"モード時は "CCB<=" を "1d100<=" に置換する（RESB/CCB固定行は変更しない）
  diceCommand: 'CCB' | 'CC' | '1d100';

  // ── 追加表示オプション（チャットパレット） ──

  // 初期値技能セクションを出力するか
  showInitialSkills: boolean;

  // 回避を【取得技能セクション】に強制追加するか
  // （取得済みの場合は重複を排除し1行のみ出力）
  showDodge: boolean;

  // 目星・聞き耳・図書館を【取得技能セクション】に強制追加するか
  // （取得済みの場合は重複を排除）
  showPerceptionSkills: boolean;

  // こぶし・キック・頭突きにダメージ行を追加するか
  // 当該技能が取得済み or showDodge等で強制追加された場合のみ適用
  showCombatDamage: boolean;

  // ── 能力値×5表示 ──
  showStatTimes5All: boolean;  // true の場合、以下の個別設定を上書きして全部ON
  showStatTimes5: {
    STR: boolean;
    CON: boolean;
    POW: boolean;
    DEX: boolean;
    APP: boolean;
    SIZ: boolean;
    INT: boolean;
    EDU: boolean;
  };

  // ── ステータス表示設定（ococofolia JSON の secret / invisible / hideStatus） ──
  hideStatus:          boolean;  // ステータスを非公開 → JSON: "secret"
  invisible:           boolean;  // 発言時キャラクターを表示しない → JSON: "invisible"
  hideStatusFromBoard: boolean;  // 盤面キャラクター一覧に表示しない → JSON: "hideStatus"

  // ── 外観 ──
  tokenSize: number;             // 駒の幅・高さ（グリッド単位）。正の整数または小数。デフォルト: 4
  useDefaultColor: boolean;      // true: JSON の "color" フィールドを省略する
  chatColor: string;             // "#rrggbb" 形式。useDefaultColor=false の場合のみ使用
}
```

### 4.5 ココフォリアJSONスキーマ（完全版）

出力するJSONの完全仕様。各フィールドの型・省略条件を明記する。

```jsonc
{
  "kind": "character",
  "data": {
    // 必須フィールド
    "name": "<string: キャラクター名>",
    "initiative": <number: DEX値>,
    "memo": "",
    "externalUrl": "",
    "width":  <number: tokenSize>,
    "height": <number: tokenSize（widthと同値）>,

    // オプション由来フィールド
    // Options.hideStatus が true の場合: "secret": true
    // Options.hideStatus が false の場合: "secret": false
    "secret": <boolean>,

    // Options.invisible が true の場合: "invisible": true
    "invisible": <boolean>,

    // Options.hideStatusFromBoard が true の場合: "hideStatus": true
    "hideStatus": <boolean>,

    // Options.useDefaultColor が false の場合のみ出力
    // Options.useDefaultColor が true の場合: このフィールドを JSON に含めない
    "color": "<string: #rrggbb>",  // ← useDefaultColor=false のときのみ

    // ステータスバー（HP/MP/SAN）
    "statuses": [
      { "label": "HP",  "value": <number: currentHP>,  "max": <number: maxHP>  },
      { "label": "MP",  "value": <number: currentMP>,  "max": <number: maxMP>  },
      { "label": "SAN", "value": <number: currentSAN>, "max": <number: initialSAN> }
    ],

    // 能力値パラメータ（表示順固定）
    "params": [
      { "label": "STR", "value": "<string: STR値>" },
      { "label": "CON", "value": "<string: CON値>" },
      { "label": "POW", "value": "<string: POW値>" },
      { "label": "DEX", "value": "<string: DEX値>" },
      { "label": "APP", "value": "<string: APP値>" },
      { "label": "SIZ", "value": "<string: SIZ値>" },
      { "label": "INT", "value": "<string: INT値>" },
      { "label": "EDU", "value": "<string: EDU値>" },
      { "label": "DB",  "value": "<string: DB値 例=+1d4>" }
    ],

    // チャットパレット
    "chatpalette": {
      "commands": "<string: 改行区切りのチャットパレット文字列>"
    }
  }
}
```

**`params[].value` は文字列型**：ococofolia の仕様上、params の value は数値ではなく文字列。DB値は `"+1d4"` 等をそのまま文字列として出力する。

**`color` フィールドの省略**：`useDefaultColor=true` のとき `color` キー自体を JSON オブジェクトに含めない（`null` や空文字列を入れるのではなく、キーごと省略）。

## 5. チャットパレット生成仕様

### 5.1 改行文字の扱い

チャットパレット文字列内の改行は **実際の改行文字 `\n`（LF）** を使用する。  
Excelシートで `" \n【..."` と書かれているものは、ヘッダー行の冒頭に「スペース + 実際の改行 + テキスト」を意味する。  
JSON出力時、`chatpalette.commands` の値は `JSON.stringify` によって `\n` がエスケープされ `\\n` になるため、**そのまま出力して問題ない**。

### 5.2 diceCommand による置換ルール

| `diceCommand` | 置換対象パターン | 置換後 |
|---|---|---|
| `CCB` | 置換なし（デフォルト） | `CCB<=` |
| `CC`  | `CCB<=` → `CC<=` | `CC<=` |
| `1d100` | `CCB<=` → `1d100<=` | `1d100<=` |

**注意**: 固定行の `CCB<= 【】` および `RESB(-)` は`diceCommand`設定に関わらず変更しない（これらは特殊コマンドであり置換不要）。

### 5.3 完全なチャットパレット出力仕様（順序・条件付き）

以下を **この順序で** 結合する。各ブロック間は空行なし（ブロック内の空行のみ記載）。

```
【ブロック A: 固定ダイス】（常に出力）
1d10
1d100
RESB(-)
{CMD}<= 【】
（空行 × 8）
{CMD}<={SAN} 【SAN値チェック】

【ブロック B: 能力値×5】（showStatTimes5All=true、または showStatTimes5.XXX=true の能力値が1つ以上ある場合に出力）
 \n【能力値×5】----------------
{CMD}<={STR}*5 【STR×5】   ← showStatTimes5All or showStatTimes5.STR=true の場合
{CMD}<={CON}*5 【CON×5】   ← showStatTimes5All or showStatTimes5.CON=true の場合
{CMD}<={POW}*5 【POW×5】   ← 同上
{CMD}<={DEX}*5 【DEX×5】   ← 同上
{CMD}<={APP}*5 【APP×5】   ← 同上
{CMD}<={SIZ}*5 【SIZ×5】   ← 同上
{CMD}<={INT}*5 【INT×5】   ← 同上
{CMD}<={EDU}*5 【EDU×5】   ← 同上

【ブロック C: 技能値】（常に出力）
 \n【技能値】--------------------
{CMD}<= 【】
（技能エントリーを順に出力 ← 後述）

【ブロック D: 初期値技能】（showInitialSkills=true かつ 初期値技能が存在する場合に出力）
 \n【初期値技能】----------------
{CMD}<={value} 【{displayName}】
（初期値技能のエントリーを順に出力）
```

`{CMD}` は `diceCommand` に基づいた接頭詞（`CCB` / `CC` / `1d100`）。

### 5.4 技能エントリー出力ルール（ブロック C）

以下の優先順位で技能リストを構築する。

**Step 1: ベースリストの構築**
- `character.skills` から `isAcquired=true` のものを取り出す
- 出力順は constants.js の SKILLS 定義順とする

**Step 2: 強制追加（重複排除）**
- `showDodge=true` かつ 回避がベースリストに未存在 → 回避を先頭に追加
- `showPerceptionSkills=true` の場合、目星・聞き耳・図書館のうちベースリストに未存在のものを末尾に追加

**Step 3: 各エントリーのフォーマット**

通常技能：
```
{CMD}<={value} 【{displayName}】
```

`showCombatDamage=true` かつ技能名が「こぶし（パンチ）」「キック」「頭突き」の場合、**技能行の直後** にダメージ行を追加：
```
{CMD}<={value} 【こぶし（パンチ）】
1d3{DB} 【こぶし ダメージ】
{CMD}<={value} 【キック】
1d6{DB} 【キック ダメージ】
{CMD}<={value} 【頭突き】
1d4{DB} 【頭突き ダメージ】
```

`{DB}` は stats.DB の値（例: `+1d4`）をそのまま連結する。DBが `+0` の場合は `1d3+0` となる。

### 5.5 初期値技能エントリー出力ルール（ブロック D）

- `character.skills` から `isAcquired=false`（value === initial）かつ `value > 0` のものを出力
- ただしクトゥルフ神話（initial=0）は value=0 のため `value > 0` 条件を満たさず出力しない
- 出力フォーマット: `{CMD}<={value} 【{displayName}】`
- ブロック D の出力対象が0件の場合、ヘッダー行も出力しない

## 6. サービス別データ取得・パース仕様

### 6.1 URL判別・ID抽出ロジック（detector.js）

```javascript
// 戻り値の型
// { service: 'iachara'|'iachara_sns'|'hokanjo'|'charaeno', id: string }
// または null（対応外URL）

const PATTERNS = [
  { service: 'iachara',     regex: /^https?:\/\/iachara\.com\/view\/(\d+)/          },
  { service: 'iachara_sns', regex: /^https?:\/\/iachara\.com\/sns\/(\d+)\/view/     },
  { service: 'hokanjo',     regex: /^https?:\/\/charasheet\.vampire-blood\.net\/(\d+)/ },
  { service: 'charaeno',    regex: /^https?:\/\/charaeno\.sakasin\.net\/6\/(\d+)/   },
];

export function detectService(url) {
  const trimmed = url.trim();
  for (const { service, regex } of PATTERNS) {
    const m = trimmed.match(regex);
    if (m) return { service, id: m[1] };
  }
  return null;
}
```

### 6.2 パーサー共通インターフェース

**すべてのパーサーは以下のシグネチャに従う**：

```typescript
// parsers/index.js で export する統一ファクトリ関数
async function parse(service: string, id: string, fetchFn: FetchFn): Promise<CharacterData>

// 個別パーサーの内部シグネチャ
async function parseIachara   (html: string, id: string): Promise<CharacterData>
async function parseIacharaSns(html: string, id: string): Promise<CharacterData>
async function parseHokanjo   (html: string, id: string): Promise<CharacterData>
async function parseCharaeno  (html: string, id: string): Promise<CharacterData>

// FetchFn: fetcher.js が提供するラッパー
type FetchFn = (url: string) => Promise<string>
```

パーサーは `html` 文字列（DOMParser でパース済みの `Document` ではなく生のHTML文字列）を受け取り、内部で `new DOMParser().parseFromString(html, 'text/html')` する。これによりパーサーのテスト時にフィクスチャHTMLを直接渡せる。

### 6.3 いあきゃら 通常（iachara.js）

#### 6.3.1 取得方法

いあきゃらは **公開APIを持たない**。また旧Excelに記載されていたAPIトークンは有効期限切れのJWT（2021年11月期限）であり使用不可。  
**HTMLページをスクレイピングする**方針を採用する。

取得URL：
```
https://iachara.com/view/{id}
```

#### 6.3.2 HTMLパース対象フィールド

| フィールド | パース方法（CSSセレクタ / テキスト位置） | フォールバック |
|---|---|---|
| キャラクター名 | `h1.pc-name` または `title` タグから先頭部分 | `"名無し"` |

#### 6.3.3 技能テーブルパース手順

```
1. document.querySelectorAll('.skill-table tr') で全行取得
2. 各行から技能名テキストと数値を取得
3. 技能名を constants.js の SKILL_NAME_NORMALIZE_MAP で正規化
4. 正規化後の名前で SKILLS 定義を検索し initial 値を取得
5. value > initial であれば isAcquired = true
```

### 7.2 ダメージボーナス計算表

STR + SIZ の合計値で DB を決定：

| STR+SIZ 範囲 | DB |
|---|---|
| 2〜12 | -1d6 |
| 13〜16 | -1d4 |
| 17〜24 | +0 |
| 25〜32 | +1d4 |
| 33〜40 | +1d6 |
| 41〜56 | +2d6 |
| 57〜72 | +3d6 |
| 73〜88 | +4d6 |
| 89〜104 | +5d6 |

```javascript
export function calcDB(STR, SIZ) {
  const sum = STR + SIZ;
  if (sum <= 12)  return '-1d6';
  if (sum <= 16)  return '-1d4';
  if (sum <= 24)  return '+0';
  if (sum <= 32)  return '+1d4';
  if (sum <= 40)  return '+1d6';
  if (sum <= 56)  return '+2d6';
  if (sum <= 72)  return '+3d6';
  if (sum <= 88)  return '+4d6';
  return '+5d6';
}
```

## 10. CORSプロキシ戦略

### 10.1 プロキシ一覧と優先順

| 優先度 | プロキシ | エンドポイント形式 | レスポンス形式 |
|---|---|---|---|
| 1（プライマリ） | allorigins.win | `https://api.allorigins.win/get?url={encoded}` | JSON `{ contents: "html" }` |
| 2（第1フォールバック） | corsproxy.io | `https://corsproxy.io/?{encoded}` | 生テキスト |
| 3（第2フォールバック） | thingproxy.freeboard.io | `https://thingproxy.freeboard.io/fetch/{url}` | 生テキスト |

すべて失敗した場合 → `AppError(PROXY_ERROR)` を throw。

### 10.2 タイムアウト設定

```javascript
const FETCH_TIMEOUT_MS = 10_000; // 10秒

async function fetchWithTimeout(url) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), FETCH_TIMEOUT_MS);
  try {
    const res = await fetch(url, { signal: controller.signal });
    return res;
  } catch (e) {
    if (e.name === 'AbortError') throw new AppError('TIMEOUT');
    throw new AppError('NETWORK_ERROR', e.message);
  } finally {
    clearTimeout(timer);
  }
}
```

### 10.3 HTTPステータス検証

プロキシ経由でも対象サイトの404は検出できる（allorigins は元サイトの status を `status` フィールドで返す）。

```javascript
// allorigins の場合
const json = await res.json();
if (json.status?.http_code === 404) throw new AppError('HTTP_NOT_FOUND');
if (json.status?.http_code >= 400) throw new AppError('HTTP_ERROR', json.status.http_code);
return json.contents;
```

## 11. エラーハンドリング仕様

### 11.1 レイヤー別対応表

| レイヤー | 対応方針 |
|---|---|
| 入力バリデーション | validator.js で事前チェック。UI にインラインエラー表示 |
| ネットワーク | try/catch + プロキシフォールバック。全失敗時は PROXY_ERROR |
| HTTPステータス | 404 と 4xx/5xx を区別。ユーザー向けメッセージを変える |
| タイムアウト | AbortController で 10 秒後に打ち切り |
| HTML パース | フィールド単位で try/catch。失敗時はデフォルト値補完 + isPartial=true |
| 数値変換 | parseInt/parseFloat 失敗時は 0 またはフォールバック値。NaN チェック必須 |
| クリップボード | Promise rejection をキャッチし CLIPBOARD_DENIED エラー表示 |

### 11.2 パーサーの防衛的実装方針

- `document.querySelector()` の結果は必ず null チェックする
- `.textContent` / `.value` は必ず `.trim()` する
- 数値フィールドは `parseInt(val, 10)` で基数を明示し、`isNaN()` チェックを行う
- 一つのフィールド取得失敗が全体クラッシュにならないよう、各フィールドを独立した try/catch で囲む

## 12. バリデーション仕様（validator.js）

### 12.1 URL バリデーション

```javascript
export function validateUrl(url) {
  if (!url || url.trim() === '') return { ok: false, code: 'URL_EMPTY' };
  const result = detectService(url);
  if (!result) return { ok: false, code: 'URL_UNSUPPORTED' };
  // ID部分が数字のみで構成されているかはregexで担保済み
  return { ok: true, ...result };
}
```

### 12.2 tokenSize バリデーション

- 型: number
- 有効範囲: 0.5 以上 10 以下
- 小数点1桁まで有効（例: 4.0, 2.5）
- バリデーション失敗時: デフォルト値 4 に戻す（エラー扱いにしない）

### 12.3 chatColor バリデーション

- 形式: `#rrggbb` (16進カラーコード 7文字)
- 正規表現: `/^#[0-9a-fA-F]{6}$/`
- バリデーション失敗時: `#888888` にフォールバック（エラー扱いにしない）

## 13. セキュリティ方針

### 13.1 DOMParser の安全な使用

CORSプロキシ経由で取得した外部HTMLを `DOMParser` でパースする際、スクリプト実行のリスクがある。

**対策**:
- `DOMParser.parseFromString(html, 'text/html')` は **スクリプトを実行しない**（仕様上安全）
- パースした `Document` を実際のDOMに `appendChild` **しない**
- `innerHTML` での挿入は一切行わない

### 13.2 JSONインジェクション対策

JSON出力文字列は `JSON.stringify()` を通じて生成するため、特殊文字は自動的にエスケープされる。  
追加の対策は不要。

### 13.3 クリップボードAPI要件

`navigator.clipboard.writeText()` は以下の環境で動作する：
- HTTPS 配信（GitHub Pages / Netlify は自動的にHTTPS）
- `localhost` でのローカル開発

HTTP環境でのフォールバック: `document.execCommand('copy')` は非推奨のため使用しない。代わりに CLIPBOARD_DENIED エラーを表示し「テキストエリアから手動でコピーしてください」と案内する。

### 13.4 外部リソース読み込みなし

CDNからの外部JSライブラリは使用しない（ゼロ依存）。依存ライブラリのサプライチェーン攻撃リスクを排除。

## 14. 外部サービス依存リスクと対策

### 14.1 各サービスのHTML構造変更リスク

本ツールは外部サービスのHTMLスクレイピングに依存するため、各サービスがHTMLを変更した場合にパーサーが動作しなくなる。

| リスク | 対策 |
|---|---|
| セレクタ変更によるパース失敗 | isPartial=true で警告表示し、取得できたフィールドのみで出力継続 |
| PARSE_FAILED エラー頻発 | GitHub Issues等でユーザー報告を受け付け、迅速にセレクタを修正 |
| サービス終了 | detector.js の対応サービスから除外し、エラーメッセージで案内 |

### 14.2 パーサーの実装前確認必須事項

**実装前に以下を必ず実際のHTMLで検証すること**：

| サービス | 確認必須項目 |
|---|---|
| いあきゃら | 能力値セルのセレクタ、技能テーブルの構造、現在値/最大値の所在 |
| いあきゃらSNS | 通常版との差分セレクタ |
| キャラクター保管所 | name属性の実際の値（NP1〜NP18 の実在確認）、技能value取得方法 |
| キャラエノ | 全フィールドのセレクタ（6版専用画面の構造確認） |

確認手順:
1. 各サービスで実際のキャラクターページをブラウザで開く
2. 開発者ツール → Elements タブでHTML構造を確認
3. セレクタを確定させ、設計書の暫定値を更新してから実装に入る

### 14.3 CORSプロキシ依存リスク

| リスク | 対策 |
|---|---|
| allorigins.win の停止 | 3段階フォールバック（§10.1）で対応 |
| プロキシのレートリミット | 全プロキシが失敗 → PROXY_ERROR でユーザーに再試行を促す |
| プロキシ経由でのHTTPS化 | 各プロキシはHTTPSエンドポイントのみ利用する |

## 18. 実装上の注意事項

1. **APIトークン不使用**: 旧Excelに記載のいあきゃらAPIトークンは2021年11月に有効期限切れのJWT。使用禁止。HTMLスクレイピングで代替する。
2. **DB値の優先順位**: API/HTMLから取得できた場合はその値を優先し、取得できない場合のみ constants.js の `calcDB()` で算出する。
3. **チャットパレット内の `\n` リテラル**: ヘッダー行（ `" \n【能力値×5】..."` 等）の冒頭スペースは半角スペース1文字 + LF改行 + テキストを意味する。JSON.stringify で `\\n` にエスケープされるのは正常動作。
4. **技能名重複排除の実装**: `showDodge` / `showPerceptionSkills` で強制追加する前に、既存リストに同名技能が存在しないか `Set` または `findIndex` で確認する。
5. **`color` フィールドの省略**: `useDefaultColor=true` の場合、JSONオブジェクト生成時にキーごと追加しない（`undefined` を渡すのではなく `delete obj.data.color` またはスプレッド構文で除外する）。
6. **クリップボード非HTTPS対策**: HTTP環境ではクリップボードAPIが使えない。代替UIとして出力テキストエリアに `select()` を呼んでフォーカスを当てる。
7. **tokenSize の JSON 出力**: `width` と `height` に同値を出力する。小数点以下は保持する（ococofolia が許容する場合）。
8. **ローカル確認方法**: `npx serve .` または `python3 -m http.server` で HTTP サーバーを立てること。`file://` では ES Modules が動作しない。
